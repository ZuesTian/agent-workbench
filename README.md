# Agent 工坊 1.0.0

本机 Agent、Skill、MCP 管理与多 Agent 协作编排工具。1.0.0 为第一版，包含资源盘点与装配、协作画布、真实任务执行、自动调度、多 Agent 会话和 Windows 托盘。

双击 `dist/AgentWorkbench/AgentWorkbench.exe` 启动。免安装目录版的 `_internal` 文件夹需和程序一起保留。分享程序请使用 `AgentWorkbench-1.0.0-Windows.zip`；本版验收记录位于 `releases/1.0.0/verification/README.md`。

界面由左侧导航、来源或记录列表、主内容区组成，支持明暗主题。窄窗口（≤1180px）将中间列表收起为抽屉，≤820px 使用图标导航。任务与协作可调用本机 Codex CLI、DeepSeek Harness、Zcode 和 Cursor Agent CLI，复用各客户端已有账号与配置。

## 启动与资源刷新

启动时先显示上次扫描结果，在后台检查本机资源；首次使用没有缓存时也会先打开界面。刷新期间顶部会标明结果状态，协作画布和任务表单可以继续使用，扫描结束不会替换正在填写的任务表单。右上角“重新扫描”也在后台完成。

扫描每次仍读取内容并核对摘要，仅复用未变化文件的解析结果；同大小、同修改时间的内容变化也会被发现。程序文件删除、配置变化和新增 Skill 会在刷新完成后更新。普通 JSON 使用标准解析器，带注释等扩展语法的配置使用 JSON5；运行中客户端通过 Windows 进程快照筛选后再读取程序路径。

启动缓存位于本机数据目录的 `cache/catalog.json`，只保存界面可见的资源摘要，不保存原始 MCP 凭据、命令参数值或 Skill 正文。缓存损坏、格式不匹配或扫描目录设置变化时会重新扫描。预览装配仍使用本次读取的配置，应用和恢复仍核对实际文件；显示缓存不参与写入授权。扫描失败时保留已有显示结果，并提供重试入口。

## 窗口与后台

启动后，Windows 右下角通知区域会显示工坊图标；如果系统将它折叠，可在托盘的 `^` 中找到。单击图标打开或恢复工坊；右键可选择 **打开工坊、最小化窗口、完全退出**。

- **最小化**：收起独立工坊窗口，任务和后台服务继续运行。可从任务栏或右下角托盘恢复。
- **关闭窗口**：只关闭界面，托盘与后台仍保留；从托盘或桌面入口重新打开。
- **完全退出**：关闭工坊窗口、移除托盘、停止后台服务并释放运行锁；会取消正在执行的任务。界面左下角与托盘菜单均提供此操作。

未保存的协作画布会保留为本机浏览器草稿，下次打开可继续；如果草稿写入失败，仍会提示保存或导出，避免静默丢失。

重复打开桌面入口会恢复已有窗口。窗口控制只作用于独立的 Edge 工坊窗口，不关闭普通浏览器的其他标签页；通过浏览器标签页访问时使用浏览器自身的最小化操作。

## 协作编排

协作画布提供层级节点、角色职责、汇报关系与审核策略。界面采用浅灰底色、白色圆角侧栏和卡片、黑灰文字与宽松留白；右上角可切换深色并记住偏好。字体使用系统字体，图标、样式和脚本随程序提供，界面无需访问外部 CDN。

1. 打开 **协作编排**，选择产品研发组、研究协作组或空白画布，填写总目标。
2. 在画布中选择节点，设置导师 / 协作者 / 子 Agent、汇报对象、职责和审核策略。可引用本机角色定义；执行模型可沿用客户端当前配置，也可从该客户端的模型列表选择。切换客户端会重置该节点的模型选择。
3. 绑定本机客户端及 Skill / MCP。点击 **在装配台预览此节点**，进入原有的变更预览、备份和应用流程。装配作用于客户端全局配置，不会创建独立运行环境；多个节点绑定同一客户端时共享该客户端配置。
4. 拖动节点会带动下级。按住 Shift 拖到另一个节点可改变上级，也可在右侧选择汇报对象。窄窗口或节点较多时，默认用“阅读节点”查看原始大小的大纲；“查看全图”才缩小以容纳整张拓扑，手动放大后不会因普通调整窗口而回到缩小状态。节点设置可以收起。支持折叠、展开、横 / 纵自动排版、缩放和结构大纲；键盘聚焦画布时 `+` / `-` 缩放，`0` 查看全图。
5. **保存 / Ctrl+S** 将协作方案写到本机；未保存草稿保留在当前浏览器。另一个窗口更新方案后，会阻止旧版本覆盖，可另存或重新载入。
6. **流程预演** 只演示交接顺序，审核步骤的“模拟通过 / 模拟打回”不会调用模型，也不会让自动调度打回或重试。切换到 **流程动态** 可查看同一份预演记录；修改目标或节点会重置预演。真实执行请点击 **执行协作**：在 **自动调度** 中选择共同工作目录、权限和每步时限。审核节点会列出需修改项；若要按意见改结果，请调整任务后再次手动执行。
7. 更多菜单中可导出协作 JSON、导出 Markdown 任务说明，或导入本工具 / NexusMind 案例导出的 JSON。导入先验证编号、上下级循环和字段大小，资源来源无法匹配时保留引用并提示重新绑定。协作方案上限为 100 个节点，导入文件上限为 2 MB。

导出协作 JSON 不嵌入 MCP 配置、认证头、环境变量值或资源文件路径。用户在目标、职责和模型栏中自行填写的文本会随方案分享。别人的电脑仍需准备对应资源并重新绑定；分享程序本身请发送根目录的 `AgentWorkbench-1.0.0-Windows.zip`，解压后双击即可启动。

`examples/` 中提供从用户 NexusMind 案例整理的三份可导入方案：`nexusmind-software.team.json`（9 节点）、`nexusmind-marketing.team.json`（6 节点）、`nexusmind-finance.team.json`（6 节点）。保留原案例的职责和模型备注，重新排版以适应新版画布；模型名称仅为原案例文本，不表示已连接或可用。

## 执行任务

侧栏 **执行任务** 支持 Codex CLI、DeepSeek Harness、Zcode 和 Cursor Agent CLI 的任务下发、日志、结果、取消与超时。复用本机已有账号与配置；Zcode 跟随桌面端的数据目录，Harness 使用 headless profile，Cursor 使用官方 CLI 配置。权限选择随客户端展示，Cursor / Zcode 的规划与编辑模式由客户端控制。

**自动调度** 运行当前协作画布的独立快照：上级先分派，子节点按层级及节点顺序执行，上级最后审核汇总。全程串行，共用工作目录，自动向后续步骤传递结果；失败停止后续步骤，取消终止当前进程树。可搜索、翻页、重新打开历史并下载汇总。质量审核内容由 Agent 输出，不自动打回重试；“已完成”只表示所有步骤正常返回，不代表业务验收通过。画布上的资源引用需先在装配台应用，多个节点绑定同一客户端时共享该全局配置。运行使用各客户端账号额度，取消不回滚文件。详细范围与验证方式见 [EXECUTION.md](EXECUTION.md)。

## 会话

侧栏 **会话** 让多个本机 Agent 在同一段对话里依次回答。新建会话时选择工作区目录和成员（Codex CLI、DeepSeek Harness、Zcode、Cursor Agent CLI 中有可用调用入口的客户端），之后每条消息会按成员顺序交给每个 Agent；它们的回复留在同一段对话里，后续消息和回复都会作为上下文一并交给下一次调用。可以只让部分成员回答，或取消本轮剩余回复。

- **工作区**：会话绑定一个已存在的项目目录，所有成员都在这个目录里执行；会话记录保存在 `%LOCALAPPDATA%\AgentWorkbench\conversations`，每次回复同时写入执行记录，可打开完整日志。
- **任务列表**：会话页右上角的“任务列表”列出每次回复对应的客户端调用、状态与耗时，并可跳转日志；列表长度与执行记录一致。
- **互斥**：同一时间只运行一轮会话；会话运行中不能启动手动任务或自动调度，反过来也一样。会话与自动调度都占用同一个执行入口。
- **权限**：Codex / Harness 默认只读，Cursor / Zcode 默认规划模式；可在“成员与工作区”逐个修改。Cursor 信任确认绑定本轮成员、权限和确切工作目录，成功提交后取消勾选。
- **输入与草稿**：Enter 发送、Shift+Enter 换行，输入法选字期间不会发送；未发送内容按会话保存在本机浏览器。忙碌拒绝时消息和草稿保留，服务端不留下假排队记录。
- **边界**：每个成员沿用各自客户端的登录、权限与沙箱设置；消息内容会交给对应客户端及其模型，工坊本身不上传数据。回复只表示客户端正常返回，不代表业务验收通过。

## 使用

1. 在 **总览** 查看找到程序文件的 Agent 客户端。仅有配置或目录的条目折叠在 **仅发现配置 / 待检查** 中，不计入程序数量；这些资源仍可用作装配来源。
2. 在 **Skills / MCP** 搜索、筛选来源，点击 `+` 加入装配台。同名资源可在详情中选具体来源；支持卡片/列表视图、只看已选、名称/来源数量排序和 `Ctrl+K` 搜索。
3. 在装配台选一个或多个目标 Agent，选择合并添加或同步 MCP。右上角可收起/打开装配台；窄窗口中以抽屉展示。
4. 点 **预览变更**，检查新增、覆盖和移除项。若出现多个配置文件，在预览窗口选择目标并点 **重新预览**；确认具体路径后点 **应用并备份**。
5. 常用组合可保存、加载、导入和导出；在 **备份记录** 中恢复原文件。

可从本机文件夹导入 Skill；完整目录中的脚本和参考文件会一并复制。可以添加自定义 MCP，也可以在设置中添加扫描目录或接入其他 Agent 的配置路径。

使用 Windows 安装记录、运行中程序路径、PATH、常见 npm / 编辑器扩展入口，以及各本地固定磁盘的常用安装目录识别客户端，并检查文件是否存在。程序装在 D / E / G 等盘符也能发现。特殊位置或免安装版可通过 **添加程序目录** 补充，最多向下查找三层、1500 个目录；这不是全盘递归搜索，未找到程序也不能直接断言已卸载。注册表中仅剩卸载记录、程序已不存在时，不计入程序数量。

支持 **DeepSeek Harness** 和 **Zcode**。Zcode 支持 `~/.zcode/cli/config.json` 中嵌套的 `mcp.servers` 和用户 Skill 目录，保留配置中的其他字段。Harness 支持 `~/.dsh/skills` 的装配，并读取 `~/.dsh/profiles/*/cordis*.yml` 中的静态 MCP 定义；动态 YAML 表达式不执行，Cordis MCP 写入尚未接入，请在 Harness 中修改。程序目录不能填进“MCP 配置文件”栏。

导入方案时，找不到的资源和目标会保留为失效项。重新选择来源并移出失效项后，才能预览和装配。覆盖同名资源的授权不会随方案加载；需要当次主动勾选。配置文件选择保存在本机草稿与本机方案中，导出方案不携带这一选择；在另一台电脑导入后须按当地实际配置重新选择。文件被移除或不再属于可写位置时会停止预览。

更新时先在旧版本窗口中点击 **完全退出**，再完整解压新版。程序、`_internal` 和说明文件应在同一个 `AgentWorkbench` 文件夹；个人数据在 Windows 用户目录，分享压缩包不包含这些数据。

恢复前会验证备份清单和文件内容；无法识别或不完整的备份不会自动改写。

## 范围

- 内置配置适配：Codex、Claude Code、Cursor、Trae / Trae CN、WorkBuddy、OpenCode、Cline、Roo Code、Windsurf、Antigravity、Claude Desktop、Gemini CLI、VS Code、DeepSeek Harness、Zcode。程序证据与配置证据分别展示；可执行文件、启动脚本或扩展入口存在不代表程序已成功启动。
- 读取常见用户级 Skill 目录、插件目录和 Claude 项目级 MCP；额外项目目录需手动添加。
- 插件文件和历史版本都会被盘点，界面标明其启用状态未核验。插件提供的专用变量、OAuth、工具白名单等不能无损转换时会阻止跨客户端写入。
- 仅修改装配目标的全局 MCP 文件；项目级配置、内置云连接器和客户端自己的权限设置仍可能提供其他能力。
- Skill 支持安装和覆盖，不因取消勾选而卸载已有文件。Codex 默认安装到共享的 `~/.agents/skills`，其他支持该目录的客户端也可能发现它。
- 子 Agent 角色页只读。资源扫描不执行任务或启动 MCP。执行页与自动调度可调用 Codex、DeepSeek Harness、Zcode、Cursor；运行时由各客户端加载自身资源与 MCP，方案中的资源引用不自动安装或授权。
- JSON / JSONC 配置会格式化，注释不保留；原始字节会备份。Codex TOML 使用 tomlkit 保留未修改内容的格式和注释。

## 本地数据和恢复

本机数据：`%LOCALAPPDATA%\AgentWorkbench`。

| 目录 / 文件 | 用途 |
| --- | --- |
| `profiles/` | 装配方案，只存引用，不含 MCP 密钥 |
| `teams/` | 协作拓扑、职责、策略和资源引用，含并发版本标记 |
| `library/` | 自定义 MCP 和导入的 Skill |
| `backups/<变更编号>/` | 修改前后的完整文件及清单 |
| `settings.json` | 额外扫描目录、自定义 Agent |
| `runtime.json` | 本机服务端口和当前会话入口 |
| `cache/catalog.json` | 可重新生成的界面目录缓存，不含原始配置正文 |
| `runs/` | 真实执行任务、日志、状态和结果 |
| `workflows/` | 协作快照、分步状态与汇总结果 |
| `conversations/` | 多 Agent 会话的成员、工作区与逐条消息 |
| `server.log` | 启动异常信息 |

原有配置和备份可能包含凭据，保存在当前 Windows 用户的本地应用数据目录。资源盘点不上传这些文件，资源详情不返回 MCP 环境变量值、命令参数或认证头值；导出方案不嵌入配置正文。执行任务时，各客户端会按任务需要向模型发送上下文；自动调度也会把前序结果交给后续客户端。执行日志会显示命令与工具输出，日志和结果保存在本机。

应用前检查来源和目标的内容摘要；预览后发生变化会停止写入。Skill 的复制、备份和恢复覆盖完整目录，包括隐藏文件、依赖文件与空目录；超过 100 MB / 10000 个条目，或内部包含符号链接/目录联接时停止装配，不静默丢弃文件。目标路径在预览后被重定向时也会停止。

备份先校验，再提交修改；提交前再次核对目标。应用失败会回滚已提交项。恢复先对整笔事务作只读检查，确认路径未被重定向、备份有效且内容未被另行修改，再开始写入。恢复过程也在移动目标前持久化暂存路径和阶段，重命名阶段中断后可在备份页重试。重复恢复会核对原内容，后来新增的内容、变化的暂存文件和路径重定向均会阻止恢复。断电、备份损坏或目录清理中断等情况仍可能需要人工处理；跨文件修改不提供操作系统级原子性。

本机服务只绑定 `127.0.0.1`，默认端口 `47831`（冲突时使用其他可用端口）。桌面入口建立会话；接口检查会话、Host、Origin 和写入请求标识。关闭窗口后服务保留，以便快速重新打开；在侧栏点击 **完全退出** 可停止服务，并等待已接受的文件操作完成。

## 开发与构建

Python 3.11+。此项目复用本机已安装的 tomlkit、PyYAML 和 json5；无需模型 API Key。

```powershell
python -m pip install -r requirements.txt
python launcher.py
```

隔离测试（写入只发生在测试目录）：

```powershell
New-Item -ItemType Directory -Path .test-artifacts -Force
python -m pip install -r requirements-dev.txt
npm ci
python -m pytest -q --tb=short --basetemp=.test-artifacts/pytest-local
node --check agent_workbench/static/app.js
npm test
python -m ruff check agent_workbench tests launcher.py build_windows.py
npm run format:check
```

界面使用原生 JavaScript 模块，无运行时前端依赖。可选开发格式检查：`npm ci` 后运行 `npm run format:check`。浏览器测试使用 `tests/ui_fixture.py` 的隔离环境与 `tests/browser_review.js`、`tests/browser_teams.js`，写入目标均位于 `.test-artifacts`。

Windows + Edge 的发布冒烟：先完全退出已有工坊，再运行 `python tests/conversations_browser_smoke.py` 和 `python tests/reliability_smoke.py`；打包后分别加 `--exe dist/AgentWorkbench/AgentWorkbench.exe` 重测。会话测试使用可控 CLI 子进程，不调用真实模型；源码覆盖四类协议，发布包覆盖 Codex / Harness / Cursor 的隔离入口。CI 配置位于 `.github/workflows/ci.yml`，执行 Python / JavaScript 测试、Ruff 与前端格式检查；远程 CI 需将本仓库推送到 GitHub 后触发。

构建 Windows 免安装目录版（需 PyInstaller 与 Pillow）：

```powershell
python build_windows.py
```

| `static/app.js` / `api.js` / `ui.js` | 事件协调、接口调用、通用界面行为 |
| `static/team-model.js` | 拓扑规则、排版、导入导出、预演顺序与草稿 |
| `static/team-view.js` / `team-controller.js` | 协作页面、保存、绑定和装配入口 |
| `static/team-canvas.js` | 画布拖动、缩放、定位和连线 |
| `static/style.css` / `collaboration.css` / `theme.js` | 共享明暗主题与协作布局 |

桌面入口用 Edge 应用窗口显示；没有 Edge 时使用默认浏览器。只在本机 Windows 环境验证过，其他客户端版本与电脑环境仍需试用确认。
